 TURN 2 — Wire hooks to spin the GUI up/down for pokemon-related conversations
═══════════════════════════════════════════════════════════════════════════════

❯ Let's go ahead and wire this up with the necesary hooks to spin up and spin
  down the gui when a conversation starts regarding pokemon / predication agent
  related conversations.

⏺ Used the update-config skill (hooks live in settings.json).

  Design:
    • Spin UP  → UserPromptSubmit hook (async), gated by a keyword grep on the
      prompt. Idempotent: start_gui_server reuses a healthy server, so only the
      first matching prompt opens a browser.
    • Spin DOWN → SessionEnd hook running the launcher's --stop.

  Key constraint that forced a design choice: the watcher does a full os.walk of
  the watched dir every second. Pointing it at the repo root would crawl
  node_modules (130 MB) + all of src/ — unusable. So the GUI watches a dedicated,
  gitignored gui-workspace/ dir, which is also where the agent writes its
  data/ / predictions/ / reports/.

  Steps:
    - Created gui-workspace/{data,predictions,reports}; gitignored /gui-workspace/
    - Pipe-tested the keyword gate:
        pok[eé]mon | pok[eé]api | pikachu | prediction[ _-]?agent   (case-insensitive)
        MATCH:  "pikachu stats", "pokemon base stats", "prediction-agent MCP",
                "pokéapi call"
        NOMATCH:"refactor the auth module"
    - Verified launcher: start → :24880, idempotent re-run "reused existing"
      (no 2nd browser), --stop → API down
    - Wrote hooks to .claude/settings.json (new, project-scoped), commands use
      ${CLAUDE_PROJECT_DIR:-<abs path>} for portability

  Hooks written:

    UserPromptSubmit (async):
      PD="${CLAUDE_PROJECT_DIR:-/Users/ppak/GitHub/Agentic-System-Demo}";
      jq -r '.prompt // empty'
        | grep -iqE 'pok[eé]mon|pok[eé]api|pikachu|prediction[ _-]?agent'
        && uv run --directory "$PD" python -m prediction_agent.gui "$PD/gui-workspace"
           >/dev/null 2>&1 || true

    SessionEnd (timeout 20):
      PD="${CLAUDE_PROJECT_DIR:-/Users/ppak/GitHub/Agentic-System-Demo}";
      uv run --directory "$PD" python -m prediction_agent.gui "$PD/gui-workspace"
        --stop >/dev/null 2>&1 || true

  Verified using the exact commands extracted from settings.json:
    ✓ JSON valid; both commands extract via jq -e
    ✓ Matching prompt ("pikachu stats please") → GUI came up on :24880
    ✓ SessionEnd command → GUI stopped
    ✓ Non-matching prompt ("refactor the parser") → stayed down

  Documented the auto start/stop in README.

  Action left to the user: project-defined hooks require approval — open /hooks
  once to review + enable (also reloads the new settings.json).

  Caveat flagged: if a terminal is killed abruptly, SessionEnd may not fire and a
  server can linger (harmless — next matching prompt reuses it). Offered an
  optional SessionStart cleanup.
